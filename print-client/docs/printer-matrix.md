## 4T530 实测状态（2026-10-12）

在一台 Windows 11 工位电脑上接入 Zenpert 4T530 后的实际观测：

| 检查项 | 结果 |
|--------|------|
| PnP 设备可见 | ✅ `zenpert 4T530`，状态 OK |
| USB 硬件 ID | `USB\VID_1203&PID_12A2` |
| 打印设备节点 | `USBPRINT\ZENPERT4T530\6&32FF8281&0&USB001` |
| 端口 | USB001 存在 |
| 绑定的驱动 | ❌ **`Generic printer device`（`prnms013.inf`，Windows 通用驱动）** |
| 打印队列 | ❌ 系统中不存在（`Get-Printer` 无此设备） |

### 结论：**阻塞于驱动未安装**

Windows 只给它挂了通用 USB 打印驱动。通用驱动只能让设备"被识别"，
不能驱动热敏标签机——没有纸张尺寸控制、没有指令集。

**直接后果**：工位软件的「读取本机打印机清单」是向操作系统查询的，
而系统中没有这台打印机的队列，**因此它在软件里根本选不到**。
这是部署的第 0 步，必须先解决，否则本表其余验证无从开始。

### 解除步骤

1. 下载并安装 Zenpert 4T530 原厂驱动（见 §驱动来源）
   - 若官网驱动装不上，可试 **TSC TE244** 驱动（先擘由 TSC 代工）
   - 安装时若报"驱动程序组件正在使用中"，用管理员身份运行 DriverWizard
2. 安装后确认 `Get-Printer` 能列出该设备
3. 在该打印机的「打印首选项」里**按实际标签纸设置纸张尺寸**（这一步最容易漏，
   设错会导致版面被缩放，本表第 2、3 项必然失败）
4. 再回到本表逐条验证

**四台全是条码标签打印机**，没有一台是普通办公打印机。这一点直接影响评估：
本文件开头列的"热敏标签机对走纸与切纸精度更敏感"这条风险，**对全部四台都成立**，
不存在"先用办公打印机过渡"的余地。

## 驱动来源

优先用**原厂或 Seagull（BarTender 背后的驱动厂）**的驱动，第三方驱动站的版本往往陈旧且有捆绑。

### 先擘 Zenpert 4T200 / 4T520

- **先擘官网资源下载**：[zenpert.cn 资源下载](http://m.zenpert.cn/cn/col.jsp?id=108)
- **Seagull 原厂驱动**：[Zenpert 4T200](https://www.bartendersoftware.com/br/resources/printer-drivers/zenpert/zenpert-4t200)、[Zenpert 4T520](https://forums.seagullscientific.com/downloads/printer-drivers/zenpert-4t520/)
- **通用驱动（4T520/4T530/4T200/4T300 共用）**：[京成云马](http://www.360code.com/service/guide/388.htm)，兼容 Win7/8.1/10 与 Server 2012/2016/2019

> **实用提示**：多方资料显示**先擘机器由 TSC 代工**，装不上原厂驱动时可改装
> **TSC TE244** 的驱动作为兜底，配合 BarTender 使用时尤其常见。
> 遇到"驱动程序组件正在使用中"这类报错，用管理员身份运行 DriverWizard 再试。

### TSC TTP-244 Pro

- **TSC 官方**：TSC 官网 Support & Download 搜 "TTP-244 Pro"，按系统位数选驱动
- **Seagull 原厂驱动**：[TSC TTP-244 Pro](https://www.seagullscientific.com/tw/downloads/printer-drivers/tsc-ttp-244-pro/)（v12.3 / v12.6，约 71.6MB）
- 常见硬件 ID：`USBPRINT\TSCTTP-244_Pro`；手动安装时端口通常选 USB001

### Datamax M-4308 Mark II

- **Seagull 原厂驱动**：[Datamax M-4308 Mark II](https://www.bartendersoftware.com/cn/resources/printer-drivers/datamax-oneil/datamax-m-4308-mark-ii)（v12.6，约 76.5MB）
- 厂商驱动（中文站，V7.4.3）：[ZOL 驱动](http://driver.zol.com.cn/detail/47/464069.shtml)
- 硬件 ID：`USBPRINT\DATAMAXM4308-MARKII013B`、`LPTENUM\DATAMAXM4308-MARKII013B`

> **注意品牌变更**：Datamax-O'Neil 现属 **Honeywell**，找驱动时若在
> Datamax 名下搜不到新版，试 Honeywell / Datamax-O'Neil 两个名字。

## 适配路径

系统走 **Windows 打印驱动**路径（research.md R5）：

1. 在工位电脑上安装该型号的官方驱动（见上）
2. 工位软件的「设置」页 → 重新读取本机打印机清单 → 选中该型号并保存
3. 按下方用例逐条验证
4. 把结论填回上面的矩阵

**不生成 ZPL/EPL 等原生指令**：那与具体型号强绑定，每接一个型号都要改代码，
与 FR-073 直接冲突。但下面第 2、3 项若在标签机上反复不达标，需要评估为该型号
单独增加原生指令通道——**届时该型号就不再满足"无需改代码"，要在结论里如实标注**。

## 每型号必跑的验证用例

以下各项必须全部通过才能记为"通过"。任一项不通过，记"不通过"并写明现象。

| # | 用例 | 判定标准 |
|---|------|----------|
| 1 | 单张出纸 | 走纸一张，不多走不漏走 |
| 2 | 版面尺寸 | 实际出纸尺寸与模板定义一致（误差 ≤1mm） |
| 3 | 元素位置 | 二维码/条码/文字位置与预览一致（偏差 ≤0.5mm） |
| 4 | 二维码可扫 | 手机与扫码枪各扫 10 次，10/10 成功 |
| 5 | 条码可扫 | 扫码枪扫 10 次，10/10 成功 |
| 6 | 中文显示 | 中文产品名/公司名无乱码、无缺字 |
| 7 | 批量连打 | 连续打印 50 张无卡纸、无错位、无漏打 |
| 8 | 静默打印 | 不弹系统打印对话框，直接出纸 |
| 9 | 缺纸提示 | 抽走纸卷后发起打印，工位端提示"打印机离线"或明确的错误 |
| 10 | 重连恢复 | 断电重启打印机后，不需重启工位软件即可继续打印 |

**第 2、3 项是关键**：这两项决定"所见即所打"是否成立，也正是标签机最容易出问题的地方。
