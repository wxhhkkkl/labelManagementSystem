执行摘要

本系统是一套面向"总部 + 多分子公司"组织形态的整体打印管理系统，包含两个使用入口：管理后台（Web/H5，总部与子公司管理员经浏览器访问）与工位软件入口（安装在 Windows 10 工位电脑上的客户端软件，内置本地打印服务）。总部在管理后台统一导入 Excel 码清单及"码—产品"对照关系文件、管理产品并完成绑定，按"公司 + 产品"维度分配码量并随单下发打印模板；子公司工位操作员在工位软件入口执行打印，软件经内置本地打印服务直连本地打印机出纸。系统以防重复打印为核心控制点——一码正常只允许打印一次，补打为唯一例外（权限下沉到子公司管理员，必填原因、全程留痕）；作废为终态操作、不可恢复。服务端部署于远程云服务器，管理后台兼容 Win10 主流浏览器，工位软件提供 Win10 安装包。

文档共 10 章：第 1–4 章为术语、背景、角色与架构，第 5 章为功能需求主体（10 组功能项、FR-01 至 FR-10，按 P0/P1 划分优先级），第 6–7 章为码状态机与数据模型，第 8–10 章为非功能需求、验收标准与待确认事项。打印机具体型号清单由甲方后续提供，适配验证作为 P0 验收项管理。

1. 术语定义

术语定义
码系统管理的最小打印单元，通常为一物一码场景下的二维码/条码字符串（100 位以内数字字母），由总部统一导入生成
码池总部导入后尚未分配给子公司的码集合（总部库存）
工位子公司内的具体作业位置，是打印操作的最小执行单元，每个工位绑定一名或多名操作员
管理后台部署于远程服务端的 Web/H5 管理界面，总部与子公司管理员通过浏览器访问，完成管理与查询操作
工位软件入口安装在工位 Windows 10 电脑上的系统软件入口（客户端），集成操作界面与本地打印服务，负责执行打印并驱动本地打印机
补打对已打印过的码在特定条件下重新打印的行为，是防重复打印规则下唯一允许的再次打印途径
作废将某个码标记为失效、禁止再打印的操作，作废后不可恢复
打印模板定义码在标签纸上的排版规则（二维码、文本、公司名、产品名等元素的位置与样式）
总部拥有系统最高管理权限的组织节点，负责码导入、产品管理、码分配与模板管理

2. 项目概述

本章说明系统建设的业务背景、建设目标与本期建设边界。

2.1 项目背景

企业下辖总部与多个分子公司，产品上使用的"码"（一物一码）由总部统一采购或生成，再分发到各分子公司在生产/包装环节打印贴附。当前缺少统一系统管理码的导入、分配、打印与追溯，存在码量底数不清、重复打印、乱打乱用、责任无法追溯等问题。

本项目拟建设一套整体打印管理系统：服务端部署在远程服务器，总部及子公司管理员通过浏览器访问管理后台完成管理与查询；工位通过安装在 Windows 10 电脑上的软件入口（内置本地打印服务）执行打印，直连本地打印机完成出标签，实现"码从总部导入、按产品按公司分配、工位打印留痕、防重复打印、可补打可作废且全程有记录"的闭环管理。

2.2 项目目标

  1. 账实一致：总部可实时查看每个分子公司、每个产品的码库存量与已打印量，杜绝码资源失控。
  2. 一码一打：任何码正常情况下只允许打印一次，从机制上杜绝重复打印导致的窜货与造假风险。
  3. 全程留痕：从导入、分配、打印、补打到作废，每一次操作均记录操作人、时间、工位与前后状态，满足审计与追责需要。
  4. 开箱即打：工位电脑安装软件入口后即可直接驱动本地打印机打印，操作界面简洁，日常作业无需复杂配置。
  5. 模板统一：打印模板由总部管理员统一管理与下发，各公司使用总部授权的模板，保证全集团标签格式一致。

3. 用户角色与权限

角色归属核心职责关键权限
总部管理员总部系统全部管理职能码导入、产品管理、码绑定、码分配、模板管理、报表查看、组织结构管理、账号管理、补打、作废
子公司管理员分子公司本公司日常管理（本期启用）查看本公司码量与打印情况、查看本公司操作记录、管理本公司工位与操作员、对本公司码执行补打与作废（须填原因）
工位操作员分子公司·工位日常打印作业在工位软件入口查看本公司被分配的产品与码、执行打印、标记打印失败

  权限矩阵原则——数据按组织隔离：子公司账号只能看到本公司的码、模板与记录；工位操作员只能操作本工位的打印任务；总部管理员可见全部数据。所有列表查询默认按此规则过滤，越权请求一律拒绝。补打权限已确认下沉到子公司：子公司管理员可直接对本公司码执行补打，无需总部审批。

4. 系统总体架构

本章描述系统的三层部署架构与打印链路的技术原理。

4.1 部署架构

系统采用"远程服务端 + 管理后台（Web/H5）+ 工位软件入口"三层结构：

层级部署位置组成说明
服务端远程云服务器Web API 服务、数据库、文件/对象存储所有业务数据与码库集中存储，各公司通过互联网访问
管理后台浏览器（Win10 Chrome/Edge）Web/H5 管理界面总部与子公司管理员的管理与查询入口，免安装，通过 HTTPS 访问远程服务端
工位软件入口工位 Win10 电脑客户端软件（操作界面 + 本地打印服务）系统的软件入口；操作员在此执行打印/补打，内置本地打印服务驱动 USB/网口打印机出纸

5.1 组织结构管理（FR-01）

编号需求项优先级

FR-01-03停用公司/工位后不可再被分配新码、不可再执行打印，历史数据保留可查P0

编号需求项优先级
FR-02-01总部管理员可创建/编辑/停用产品；产品信息含名称、编码、规格、关联默认打印模板P0

5.3 码导入（FR-03）

编号需求项优先级
FR-03-01总部管理员可下载标准 Excel 导入模板。导入包含两类文件，需同时导入、成对校验：① 码清单文件（列：码值）；② "码—产品"对照关系文件（列：码值、产品编码）P0
FR-03-02码值格式规范：100 位以内、仅限数字与字母；导入时逐行校验格式、长度、唯一性；单次建议支持 10 万行级P0
FR-03-03码值全库唯一：与已有码重复的行整批拒绝或按行跳过（策略可配置，默认整批拒绝并输出错误清单）P0
FR-03-04导入完成后生成导入批次记录：批次号、两个文件名、总行数、成功数、失败数、失败明细下载（含对照关系中码值缺失、产品编码不存在等错误类型）、操作人、时间P0
FR-03-05导入成功且对照关系校验通过的码按对照关系完成产品绑定并进入总部码池，初始状态为"待分配"；对照关系中引用了不存在产品的行计入失败明细，不入库P0

5.4 码与产品绑定（FR-04）

编号需求项优先级
FR-04-01码在导入时通过"码—产品"对照关系文件完成产品绑定；也支持导入后在码池中按批次批量绑定/换绑产品P0
FR-04-02已分配的码不允许换绑产品；已打印的码不允许任何绑定变更P0
FR-04-03一个码同一时间只能属于一个产品（一码一产品）P0

5.5 码分配（FR-05）

编号需求项优先级
FR-05-01总部管理员按"公司 + 产品"维度将码池中的码分配给分子公司：选择目标公司、产品、分配数量，系统从码池自动取码（默认按导入批次先进先出）P0
FR-05-02支持选择特定批次/码段进行定向分配P1
FR-05-03分配生成分配单：单号、公司、产品、码数量、码段范围、分配人、分配时间、携带的打印模板P0
FR-05-04分配成功后码状态置为"已分配"，归属公司可见；总部可将未打印的码回收（回收后码回到码池，状态回"待分配"），已打印的码不可回收P0
FR-05-05总部看板可查看：各公司、各产品的"已分配未打印"码量与"已打印"码量，支持导出 ExcelP0

5.6 模板管理（FR-06）

编号需求项优先级
FR-06-01总部管理员可新建/编辑/停用打印模板；模板定义纸张尺寸、元素清单（二维码/条码、产品名、公司名、批次号、打印日期等）及其坐标、字体、字号P0
FR-06-02模板支持可视化编辑（拖拽定位 + 实时预览），并提供打印预览功能P1
FR-06-03模板带版本号：模板修改后生成新版本，历史版本保留；已被分配单引用的模板版本内容冻结，不受后续修改影响P0
FR-06-04模板随码分配携带：分配码时必须指定（默认取产品绑定的默认模板）一个模板版本，子公司工位打印时强制使用该版本，子公司不可修改模板P0
FR-06-05模板中的动态字段（如产品名、公司名、码值）由系统在打印时自动填充P0

5.7 打印管理（FR-07）

编号需求项优先级
FR-07-01工位操作员在工位软件入口中按产品查看本公司"已分配未打印"的码，选择数量（或扫码定位单个码）发起打印P0
FR-07-02打印时系统自动渲染"分配单携带的模板版本 + 码数据"，经工位软件内置的本地打印服务驱动工位绑定的打印机出纸，支持静默打印P0
FR-07-03防重复打印：打印采用"预占—确认"机制——点击打印即锁定所选码并置为"打印中"，打印确认（或本地打印服务返回成功回执）后置为"已打印"；处于"已打印"状态的码再次发起打印时系统直接拒绝P0
FR-07-04打印异常（缺纸、离线、打印服务未启动等）时操作员可对"打印中"的码执行"标记失败"，码回退为"已分配未打印"，可再次正常打印，不算补打P0
FR-07-05补打：总部管理员与子公司管理员均可对"已打印"的码发起补打（补打权限已确认下沉到子公司，子公司管理员对本公司码直接可补打，无需总部审批；工位操作员无补打权限）；补打必须填写原因；补打次数、补打人、补打时间全程记录P0
FR-07-06作废：总部管理员与子公司管理员可对权限范围内的码执行作废（子公司管理员仅限本公司码），作废须填写原因并留痕；作废后的码在任何工位不可见、不可打印、不可恢复P0
FR-07-07每一次打印动作（含正常打印、补打、打印失败）生成打印记录：码值、产品、公司、工位、操作员、打印机、模板版本、打印时间、打印类型（首次/补打）、结果P0
FR-07-08支持批量打印（一次任务连续打印多个码）与单码补打；批量任务逐码记录P1

6. 核心业务流程

本章以码状态机为核心，描述正常打印主流程与补打/作废异常流程。

6.1 码状态机

当前状态触发动作目标状态执行角色
待分配（总部码池）分配已分配总部管理员
已分配打印（预占锁定）打印中工位操作员
打印中打印成功确认已打印系统/操作员
打印中标记打印失败已分配工位操作员
已打印补打已打印（补打次数+1）总部/子公司管理员
待分配 / 已分配 / 已打印作废已作废（终态）总部/子公司管理员
已分配总部回收待分配总部管理员

  已作废为终态，不允许流转到任何其他状态。

6.2 主流程（正常打印）

  1. 总部管理员在管理后台同时导入码清单与"码—产品"对照关系文件 → 系统成对校验后码进入码池并完成产品绑定。
  2. 总部管理员按"公司 + 产品 + 数量"分配码，并随单携带打印模板版本。
  3. 子公司工位操作员登录工位软件入口，选择产品，查看本公司可打印码。
  4. 选择数量发起打印 → 系统锁定码并渲染模板 → 工位软件内置本地打印服务驱动打印机出纸。
  5. 打印成功后码置为"已打印"，生成打印记录；总部看板实时更新。

6.3 异常流程（补打/作废）

  • 补打：已打印的码若标签损坏/丢失，由总部管理员或本公司子公司管理员发起补打（必填原因）→ 系统再次渲染原模板出纸 → 补打记录入台账。
  • 作废：码判定不再使用（如整批报废）时由总部管理员或本公司子公司管理员作废（必填原因）→ 码全集团不可打印，记录入台账。
