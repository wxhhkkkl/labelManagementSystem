# 宪章合规复核（T163）

**日期**：2026-10-12 | **宪章版本**：1.0.0 | **复核范围**：T001 ~ T163 全部实现工作

本文件逐条核对 `.specify/memory/constitution.md` 的六条原则，
并记录一处**未完全满足**的条款及其处置方式。

---

## 一、测试先行 Test-First（NON-NEGOTIABLE）

### ✅ 已通过宪章修订处置（1.0.0 → 2.0.0）

**1.0.0 时的要求**：

> 测试 MUST 在实现之前编写；测试 MUST 先运行并失败（Red），然后才编写实现。

**实际执行情况**：

| 要求 | 1.0.0 下 | 2.0.0 下 |
|------|----------|----------|
| 测试在实现之前**编写** | ✅ 满足 | ✅ 满足 |
| 测试在实现之前**运行并失败** | ❌ 未逐个执行 | 不适用（已降为 SHOULD） |

T001–T163 的八个阶段都做到了「测试文件先于实现文件创建」，
但只在若干检查点整体跑套件，没有对每组测试单独执行 Red 阶段。

### 处置：修订宪章原则一

经提出三个选项（记录偏差 / 补做 Red / 修订原则）后，**用户选择修订**。
修订已完成，版本 **1.0.0 → 2.0.0**（MAJOR，既有原则语义被向后不兼容地重定义）：

- 原则名由「测试优先」改为「测试先行」
- 运行测试至失败由 MUST 降为 **SHOULD**
- NON-NEGOTIABLE 标记保留——测试先行本身仍不可协商

完整修订理由与代价说明见 `.specify/memory/constitution-amendment-2.0.0.md`。

**需要如实保留的记录**：这是**降低标准**，不是发现旧规则有误。
Red 阶段能提前发现的两类问题（断言写错、测试未覆盖目标行为）依然存在，
降为 SHOULD 后不再被强制拦截。本次实现中测试确实抓到了多个真实缺陷
（含两个只在并发下暴露的严重问题：`SKIP LOCKED` 因优化器选错索引而形同虚设、
模板版本冻结在补打路径上缺失），但那是在**运行阶段**抓到的，不是 Red 阶段。

我**没有**擅自改用 SQLite 跑集成测试（那会违反 research.md R2 的并发语义要求），
而是先问你怎么处理。

`.env` 的修改也是在你点头后才做。

## 四、简单优先 Simplicity First

### ✅ 满足

| 检查项 | 证据 |
|--------|------|
| 不写需求之外的功能 | 未引入 Redis、Celery、消息队列；轮询替代长连接；导出用 CSV/xlsx 而非引入报表库 |
| 不为一次性代码引入抽象 | 未引入共享代码包（宪章原则六也禁止）；测试辅助函数保持扁平 |
| 生产阶段主动删减 | 清理了自己写的内联 `__import__`、不存在的 `operator_fallback`、无用的占位函数与恒真断言 |

**一处有意识的例外**：`print-client` 与 `admin-web` 各自实现了一份渲染规则。
这不是过度设计，是**宪章原则六强制的结果**（两端 MUST NOT 交叉引用），
代价已在 research.md R6 中记录。

## 六、双端分离架构 Two-Tier Architecture

### ✅ 满足

| 检查项 | 证据 |
|--------|------|
| 管理后台 Python FastAPI + Vue | ✅ |
| 打印软件端 Electron | ✅ |
| **打印端 MUST NOT 直连数据库** | ✅ 工位端只有 HTTP 客户端，无任何数据库依赖；有契约与实现双重保证（FR-076） |
| 两端代码/依赖/构建配置相互隔离 | ✅ 三个独立目录，各自 `package.json` / `pyproject.toml`，无交叉引用 |
| 跨端契约变更两端同步 | ✅ 每处契约变更（如任务轮询增加 `elements_json`）都同步更新了 `contracts/` 与两端实现 |

**一处需要你知道的边界**：`print-client` 里的本地打印服务与工位界面之间
走的是**本机回环 HTTP**（127.0.0.1），不承载业务数据。
这符合"两端不共享业务数据通道"的要求，但它确实是跨进程通信——
如果你认为这也算"交叉引用"，告诉我。
